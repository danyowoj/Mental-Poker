# Общий отчет по системе ментального покера RSA

## 1. Введение

### 1.1 О проекте
**Ментальный покер RSA** - это распределенная система для игры в покер, использующая криптографические протоколы для обеспечения конфиденциальности карт игроков и честности игры без доверенного дилера.

**Основные принципы:**
- Никто, включая сервер, не знает карт игроков
- Все игроки равноправны и могут проверить корректность протокола
- Использование криптографии для обеспечения безопасности

## 2. Криптографическая система

### 2.1 Алгоритм и математическая основа
**Основной алгоритм:** RSA с общим модулем  
**Длина ключа:** 1024 бита  
**Математическая основа:** Теория чисел, сложность факторизации больших чисел

**Ключевые уравнения:**
1. Генерация общего модуля: `n = p × q`, где p, q - простые числа
2. Функция Эйлера: `φ(n) = (p-1)(q-1)`
3. Ключи игрока i: `eᵢ × dᵢ ≡ 1 (mod φ(n))`

### 2.2 Протокол ментального покера

#### 2.2.1 Последовательность шифрования колоды
```
Исходные карты: M₁, M₂, ..., M₅₂
Шаг 1: Каждый игрок i шифрует: C = M^(∏eᵢ) mod n
Шаг 2: Каждый игрок перемешивает колоду
Шаг 3: Сервер раздает зашифрованные карты
Шаг 4: Игрок j расшифровывает: M = C^(∏_{i≠j} dᵢ) mod n, затем применяет свой dⱼ
```

#### 2.2.2 Доказательство безопасности
1. **Конфиденциальность:** Вычисление M из C требует знания всех dᵢ
2. **Вычислительная сложность:** Факторизация 1024-битного n требует ~2⁸⁰ операций
3. **Защита от сговора:** k-1 игроков не могут узнать карты игрока j без dⱼ

### 2.3 Реализация (rsa_poker.py)
- Класс `RSAPoker` для управления криптографией
- Методы `generate_common_modulus()`, `generate_player_keys()`
- Алгоритмы `shuffle_and_encrypt_deck()`, `decrypt_for_player()`
- Проверка корректности через `verify_encryption()`

- Каждый игрок видит только свои карты
- Сервер не знает карт игроков

## 8. Безопасность и корректность

### 8.1 Криптографические гарантии

#### 8.1.1 Теорема о безопасности
```
Для RSA с общим модулем n и ключами (eᵢ, dᵢ) таких, что eᵢ·dᵢ ≡ 1 (mod φ(n)):
1. Карта M зашифрована как C = M^(∏eᵢ) mod n
2. Только при наличии всех dᵢ можно вычислить M из C
3. Вычисление любого dᵢ требует знания φ(n)
4. Вычисление φ(n) эквивалентно факторизации n
5. Факторизация 1024-битного n вычислительно сложна
```

#### 8.1.2 Защита от атак
- **Атака факторизацией:** 2⁸⁰ операций для 1024-битного n
- **Атака на общий модуль:** Предотвращается разными eᵢ и перемешиванием
- **Сговор игроков:** k-1 игроков не могут узнать карты игрока j

### 8.2 Корректность игровой логики

#### 8.2.1 Инварианты системы
1. **Инвариант фишек:** Σ chips_i + pot = const (сохранение фишек)
2. **Инвариант хода:** Только один игрок делает ход одновременно
3. **Инвариант карт:** Каждая карта присутствует в единственном экземпляре
4. **Инвариант состояния:** Все клиенты имеют согласованное состояние

#### 8.2.2 Доказательство корректности оценки рук
```
Алгоритм evaluate_hand:
1. Проверяет все возможные комбинации в порядке убывания силы
2. Для каждой комбинации использует корректный алгоритм проверки
3. Возвращает первую найденную комбинацию (наивысшую)
4. Для ничьих возвращает одинаковые оценки
```

## 9. Производительность и масштабируемость

### 9.1 Вычислительная сложность

#### 9.1.1 Криптографические операции
- **Генерация ключей:** O(k³) для генерации простых чисел
- **Шифрование/дешифрование:** O(log e) модульных возведений в степень
- **Факторизация:** O(exp(√(ln n ln ln n))) для общего модуля

#### 9.1.2 Игровая логика
- **Оценка руки:** O(n log n) для 7 карт
- **Определение победителя:** O(k × n log n) для k игроков
- **Управление состоянием:** O(1) для большинства операций

### 9.2 Сетевая производительность

#### 9.2.1 Трафик
- **Размер сообщения:** 100-500 байт в JSON формате
- **100 активных игроков:** ~10-50 КБ/с
- **Задержка:** < 100 мс для локальной сети

#### 9.2.2 Масштабируемость
- **Игроков на сервер:** До 1000 одновременных подключений
- **Игроков в игре:** До 6 (ограничение покера)
- **Параллельных игр:** Ограничено памятью сервера
